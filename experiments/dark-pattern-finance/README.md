# 모아핏 모바일 의사결정 체험

이사에 필요한 생활자금 300만원과 여윳돈 100만원을 관리할 구성을 고르는 연구용 가상 금융 앱입니다. 상품 선택이 다음 단계의 설정과 예상 비용에 누적되며, 마지막에 구성을 수정하거나 전체 신청을 보류할 수 있습니다. 실제 계좌 개설·대출·투자·환전·결제는 발생하지 않습니다. 상품·요금·이용자 활동 알림은 연구용 모의 정보입니다.

설문 문항이나 응답을 생성·수집하지 않습니다. 앱의 선택·행동 기록과 최종 모의 결정을 남기며, 현재는 체험 후 같은 홈페이지의 임시 복귀 페이지에 패널 ID와 완료·아웃 상태값을 전달합니다. 실제 엠브레인 설문으로의 복귀는 운영 주소와 코드가 확정된 뒤 전환합니다.

## 실행 파일과 현재 연동 상태

별도 빌드나 외부 라이브러리 없이 다음 파일을 같은 디렉터리에서 HTTP(S)로 제공합니다. 배포 경로는 `/experiments/dark-pattern-finance/`입니다.

- `index.html`: 화면의 기본 영역과 스크립트 연결
- `app.css`: 모바일 레이아웃, 읽기 쉬운 글자·버튼, 조건별 배치와 강조
- `panel-config.js`: 조사 ID, 운영 복귀 주소·상태 코드, 선택적인 기록 수집 주소
- `panel-bridge.js`: 패널 ID 검증·보존, 복귀 URL 생성, 최종 기록의 서버 저장 확인
- `session-sync.js`: 선택·클릭 기록의 기기 내 대기열, 재시도, 서버 저장 확인
- `panel-return.html`, `panel-return.js`: 실제 설문을 대신하는 임시 복귀 확인 화면
- `server/`: Supabase 데이터베이스와 수집 함수의 배포 소스·검증·운영 안내
- `app.js`: 단계별 문구, 상품 조건, 선택과 비용, 진행·기록·복구·복귀 화면

현재 앱 버전은 `2026-11-21.1`, 진행 기록 형식은 `schemaVersion: 4`입니다. 사용자가 실제 운영 URL이 오기 전 임시 URL 시험과 **체험 중단의 아웃 처리**를 승인하여, `panel-config.js`는 `enabled: true`, `testMode: true`, `exitIsOut: true`로 설정되어 있습니다.

- **임시 복귀 시험:** 같은 홈페이지의 `panel-return.html?mode=test`로 ID와 `TEMP_COMPLETE` 또는 `TEMP_OUT`을 전달합니다. 이는 실제 패널사의 완료·아웃 접수가 아닙니다.
- **서버 자동 수집:** 클라이언트의 대기열·재시도·저장 확인 코드와 Supabase 서버 소스는 준비되어 있습니다. 현재 원격 수집 서버는 배포·연결되지 않았으며 `collectionUrl`은 빈 값, `collectionRequired`는 `false`입니다. 선택·행동 기록은 현재 기기에 보관되고 서버에 아직 자동 누적되지 않습니다.
- **실제 조사 연동:** 패널사가 지정한 운영 복귀 주소·완료 코드·아웃 코드와 서버 연결을 확정하고 왕복 검증한 뒤 적용합니다. 소스 작성·로컬 테스트·임시 복귀 시험 통과와 실서비스 연동 완료를 구분합니다.

## 참가자와 연구자 URL

| 용도                        | URL 예시                                                                                              |
| --------------------------- | ----------------------------------------------------------------------------------------------------- |
| 다크패턴 조건의 패널 참가자 | `https://saeromlee.kr/experiments/dark-pattern-finance/?condition=dark&panel_id=P001`                 |
| 중립 조건의 패널 참가자     | `https://saeromlee.kr/experiments/dark-pattern-finance/?condition=neutral&panel_id=P002`              |
| 연구자 확인                 | `https://saeromlee.kr/experiments/dark-pattern-finance/?condition=dark&researcher=1&panel_id=TEST001` |
| 패널 복귀 없는 일반 체험    | `https://saeromlee.kr/experiments/dark-pattern-finance/?condition=dark`                               |
| 기존 익명 코드 방식         | `https://saeromlee.kr/experiments/dark-pattern-finance/?condition=neutral&pid=P003`                   |

위 ID는 URL 형식을 보여 주는 예시입니다. 현재 링크로는 임시 복귀 시험을 진행합니다. 실제 조사에서는 엠브레인이 전달하는 ID를 사용합니다. `condition=neutral` 이외에는 다크패턴 조건이 적용됩니다. `researcher=1`은 자극 설명과 현재 기록·내보내기를 확인하는 연구자용 표시이므로 참가자 링크에서 제거합니다. 연구자 패널에서 조건을 전환하면 패널 ID가 이어지지 않을 수 있으므로, 참가자 입장 링크는 위 형식으로 별도 구성합니다.

`panel_id`가 있거나 `panel=1`이면 패널 모드입니다. `panel_id`는 `pid`보다 우선하며, 읽은 ID의 문자나 대소문자를 임의로 제거·변환·잘라내지 않습니다. 앞뒤 공백도 포함해 유효한 원문을 그대로 기록과 복귀에 사용합니다. 다음 입력은 원문을 바꾸는 대신 오류로 처리합니다.

- ID가 없거나 빈 값·공백만 있는 값
- `panel_id`가 여러 번 들어 있는 링크
- 512자를 넘거나 제어 문자를 포함한 값
- `[ID]` 등 예시 문자가 그대로 남은 값

패널사는 ID를 URL 쿼리 값으로 인코딩해야 합니다. 특히 ID 안의 `+`는 `%2B`, `&`는 `%26`으로 전달해야 합니다. 앱은 `URLSearchParams`로 한 번 읽고 복귀 주소에도 같은 방식으로 설정하여 이중 인코딩을 피합니다.

기존 `pid`는 패널 모드가 아닐 때 지원하는 선택적 익명 코드입니다. 기존 방식대로 영문·숫자·밑줄·하이픈만 남기고 최대 48자로 제한합니다. 이 필터는 `panel_id`에는 적용하지 않습니다. 이름·연락처·실제 금융정보를 ID에 넣지 않습니다.

## 한국어 명칭과 8단계 흐름

시작 화면에서 과제를 확인한 뒤 다음 8단계를 진행합니다. 금리·요금·기간은 유지하고 상품명과 설명을 쉬운 한국어로 바꿨습니다. 내부 선택값은 기록 호환성을 위해 유지합니다.

| 구분        | 화면 표시명                     | 내부 값                         |
| ----------- | ------------------------------- | ------------------------------- |
| 저축        | 차곡차곡 적금                   | `account: flex`                 |
| 입출금 통장 | 자유 입출금 통장                | `account: basic`                |
| 대출        | 든든 생활대출 / 알뜰 생활대출   | `loan: A` / `B`                 |
| 투자        | 주식 중심 투자 / 채권 중심 투자 | `portfolio: growth` / `balance` |
| 관리 방식   | 기본 관리 / 맞춤 관리           | `plan: basic` / `plus`          |
| 추가 혜택   | 지출관리 플러스                 | `care: yes` / `no`              |

| 단계           | 선택 내용                                       | 다크패턴 조건의 표현                                                                                                                                                              |
| -------------- | ----------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. 이용할 통장 | 차곡차곡 적금 또는 자유 입출금 통장             | T04 숨겨진 정보: 최대 연 5.2%의 적용 조건을 접힌 항목 안에 배치                                                                                                                   |
| 2. 대출 비교   | 든든 생활대출, 알뜰 생활대출 또는 신청 안 함    | T05 가격비교 방해: 상품을 전환해야 다른 상품 조건을 확인                                                                                                                          |
| 3. 투자 구성   | 주식 중심 투자, 채권 중심 투자 또는 계좌에 보관 | T07 다른 소비자의 활동 알림: 조회·최근 선택 인원 제시                                                                                                                             |
| 4. 관리 방식   | 무료 기본 관리 또는 월 9,900원 맞춤 관리        | T02a 잘못된 계층구조: 설명 카드와 선택 버튼의 대응 순서를 어긋나게 구성. T02b 감각조작: 움직이는 강조 배너와 9초 뒤 재권유. 미선택 상태에서 추천 구성으로 계속하면 맞춤 관리 선택 |
| 5. 추가 서비스 | 해외시황 알림·잔액보호 보고서 유지 또는 해제    | T03 특정옵션의 사전선택: 첫 방문 때 두 유료 항목을 체크                                                                                                                           |
| 6. 자동환전    | 신청 또는 신청 안 함                            | T01 속임수 질문: 신청을 원하지 않는지 묻는 부정 질문과 예·아니요 선택                                                                                                             |
| 7. 혜택 설정   | 지출관리 플러스 신청 또는 신청 안 함            | T06 감정적 언어사용: 거절자를 부정적으로 묘사하는 문구                                                                                                                            |
| 8. 최종 확인   | 항목 수정, 모의 신청 또는 전체 신청 보류        | 현재 선택과 예상 비용을 확인한 뒤 대화상자에서 최종 결정                                                                                                                          |

자동환전의 실험 조건 질문은 “신청을 원하지 않으시나요?”입니다. **예는 미신청(`autoFx: no`), 아니요는 신청(`autoFx: yes`)**으로 저장합니다. 중립 조건의 긍정형 질문에서는 예가 신청, 아니요가 미신청입니다.

중립 조건은 상품·요금·과제를 유지하면서 금리 조건을 바로 보여 주고, 대출 비교표와 두 상품을 함께 제시합니다. 활동 알림·움직이는 권유 배너는 없고 관리 방식을 명시적으로 선택합니다. 추가 서비스는 처음부터 해제되며, 자동환전과 지출관리 플러스에는 중립적인 신청·거절 문구를 사용합니다.

## 임시 복귀 시험과 엠브레인 운영 전환

운영 흐름은 **엠브레인 설문 → `panel_id`와 함께 체험 앱 입장 → 체험 종료 → ID·상태값과 함께 엠브레인 설문 복귀**입니다. 패널사가 뒤쪽 설문을 이어서 보여 주고 최종 조사를 종료합니다. 현재는 마지막 엠브레인 설문을 같은 홈페이지의 임시 복귀 화면으로 대신합니다.

### 현재 시험 설정

| 설정                 | 현재 값과 의미                                                                      |
| -------------------- | ----------------------------------------------------------------------------------- |
| `enabled`            | `true`: 복귀 기능 활성화                                                            |
| `testMode`           | `true`: 임시 복귀·시험 기록으로 구분                                                |
| `studyId`            | `finance-decision-20261120`: 조사 식별값                                            |
| `completeReturnUrl`  | `https://saeromlee.kr/experiments/dark-pattern-finance/panel-return.html?mode=test` |
| `outReturnUrl`       | 완료와 동일한 임시 복귀 주소                                                        |
| `completeStatus`     | `TEMP_COMPLETE`: 시험용 완료 코드                                                   |
| `outStatus`          | `TEMP_OUT`: 시험용 아웃 코드                                                        |
| `exitIsOut`          | `true`: 확인을 거친 명시적 체험 중단을 아웃으로 처리                                |
| `redirectDelayMs`    | `1200`: 준비 완료 후 복귀 이동까지 대기 시간(ms)                                    |
| `collectionUrl`      | 빈 값: 원격 수집 서버 미연결                                                        |
| `collectionRequired` | `false`: 서버 미연결 단계에서도 임시 복귀 시험 허용                                 |

임시 복귀 화면은 참여번호와 상태 코드를 확인하는 시험 화면입니다. 임시 페이지 도착이나 확인 문구만으로 서버 데이터 저장을 증명하지 않습니다. 원격 수집 서버를 연결하기 전에는 UI에서 기기 내 기록 보관 상태를 구분합니다.

시험용 `session_id`·`receipt_id`는 체험 앱과 같은 출처의 `panel-return.html`에만 추가합니다. 로컬 검증에서는 복귀 주소도 로컬 출처로 함께 바꾸어야 합니다. 운영용 외부 설문에는 계약된 `panel_id`·`status`만 전달합니다.

참가자 URL에 임의로 넣은 `return_url`은 사용하지 않습니다. 복귀 주소는 배포 설정 파일에서만 읽으며, 기존 조사별 쿼리는 보존한 채 `panel_id`와 `status`만 설정합니다. 같은 이름의 쿼리가 이미 있으면 새 값 하나로 대체하고 URL 조각(`#...`)은 제거합니다. `XXXX`, `[ID]` 등 자리표시가 남은 주소는 차단합니다. 현재 임시 상태 코드와 예시의 `001`을 실제 운영 코드로 간주하지 않습니다.

### 체험 결과와 패널 상태

- 최종 모의 신청(`finalDecision: apply`)과 전체 신청 보류(`finalDecision: decline`)는 **둘 다 체험 완료(`panelOutcome: complete`)**입니다. 금융상품 거절 자체를 아웃으로 처리하지 않습니다.
- 사용자가 확인한 **체험 중단 = 아웃** 규칙에 따라, 중단 확인 버튼을 누르면 `panelOutcome: out`, 사유 `participant_exit`를 기록하고 아웃 코드로 복귀합니다. 임의의 나이·상품 선택·시간 기준으로 참가자를 제외하지 않습니다.
- 창을 닫는 것만으로 복귀 이동을 보장할 수 없습니다. 창 닫기 시 남은 기록 전송을 시도하되, 자동으로 아웃 상태를 보내지는 않습니다.
- 연결 실패 시 기록을 기기에 남기고 재연결을 제공합니다. 이미 이동을 시도한 화면을 다시 열면 자동 반복 이동 대신 재이동 버튼을 표시합니다. `panelReturn.state: returned`는 브라우저의 이동 시도 기록이며 엠브레인 서버의 수신 성공 확인이 아닙니다.

### 실제 운영으로 전환할 때

1. 패널사가 확정한 `completeReturnUrl`, `outReturnUrl`, `completeStatus`, `outStatus`로 시험값을 교체합니다. 선행 0을 보존하도록 상태 코드는 문자열로 지정합니다.
2. 실제 수집 서버를 배포·검증하고 `collectionUrl`을 연결합니다. `collectionRequired: true`로 바꾸어 최종 저장 성공을 확인한 뒤 복귀하도록 설정합니다.
3. 클라이언트 `testMode: false`, 서버 `MOA_FORCE_TEST=false`를 함께 전환하고 운영용 `studyId`를 클라이언트와 서버 `MOA_STUDY_ID`에 일치시킵니다. 시험 기록과 운영 기록을 분리하고, 이미 시작한 시험 세션을 운영 세션으로 바꾸지 않습니다.
4. `exitIsOut: true`와 체험 중단의 상태 의미를 패널사에도 전달하고, 패널사가 제공한 시험 ID로 설문 → 체험 → 설문의 실제 왕복을 검증합니다.

시험에서 운영으로 전환할 때에는 클라이언트 `studyId`와 서버 `MOA_STUDY_ID`를 같은 새 운영 조사 번호로 바꿉니다. 연결 전 기기에 남은 시험 대기열이 운영 자료로 전송되지 않도록 시험 조사 번호를 재사용하지 않습니다.

운영 주소와 코드가 확정되기 전에는 임시 복귀까지만 검증 완료로 보고합니다. 실제 패널사 주소에 임의의 가짜 완료 건을 보내지 않습니다.

## 기록 저장·자동 전송·세션 복구

화면 진행 상태는 해당 탭의 `sessionStorage`에 보관됩니다. 새로고침 복구 시 저장 형식(`schemaVersion`), 앱 버전, 실험 조건, 참가자 코드, 정확한 `panel_id`, `studyId`, 진행 단계가 일치해야 합니다. 다른 패널·다른 조사·다른 조건이나 일반 `pid` 체험의 기록을 이어서 사용하지 않습니다.

선택·변경·앱 동작 버튼 클릭·단계 진입과 이탈 등을 기록할 때마다 `revision`과 이벤트 순서를 갱신합니다. `session-sync.js`는 최신 세션 기록을 먼저 `localStorage`의 세션별 대기열에 보관하고, 수집 주소가 있을 때 자동 전송합니다. 짧은 연속 동작은 최신 기록으로 묶되 누적 이벤트를 보존합니다. 전송 실패·새로고침 이후에는 같은 세션 ID와 쓰기 토큰을 사용해 다시 시도하며, 온라인 복귀와 다음 접속 때 남은 전송을 재시도합니다.

두 저장소는 역할이 다릅니다. `sessionStorage`의 화면 복구는 해당 탭에 한정되며, `localStorage`의 미확인 전송 기록은 같은 브라우저·같은 출처에 남아 재전송에 쓰입니다. 기기나 브라우저를 바꾸면 이어지지 않습니다. 브라우저 데이터를 지우거나 저장소가 차단되면 기록 보관을 보장할 수 없으므로 경고를 확인하고 필요한 파일을 보관합니다. 서버 확인 전 기록을 단순히 제거하지 않습니다.

**현재 `collectionUrl`이 비어 있으므로 자동 전송은 대기 상태이고, 기록은 기기에만 보관됩니다.** 임시 복귀 URL에는 ID·상태값과 설정된 시험 확인 정보만 전달하며 전체 선택·행동 기록을 URL에 붙여 공개하지 않습니다. 일반 체험 완료 화면이나 연구자 모드에서 자료를 파일로 저장할 수 있습니다.

- `sessionId`, `participantCode`, `panel_id`, `studyId`, `condition`, `appVersion`, `isTest`: 세션·참가자·조사·조건·시험 구분
- `revision`, `events[].sequence`: 갱신 번호와 누적 이벤트 순서
- `initialChoices`: 항목에 처음 기록된 값. 사전 체크도 포함하므로 최초의 명시적 사용자 선택과 동일하게 해석하지 않음
- `choices`: 마지막으로 구성한 선택. 전체 신청 보류 시에도 검토한 구성을 보존
- `finalDecision`: 모의 신청 `apply`, 전체 보류 `decline`
- `panelOutcome`, `panelStatus`, `panelReturn`: 진행·완료·아웃, 복귀 코드, 저장·복귀 진행 상태
- `final_decision` 이벤트와 `costSnapshot`: 최종 확정 시 선택·비용 사본
- `events`: 선택·수정·앱 동작 버튼 클릭, 기본값, 단계 진입·이탈, 자극 노출, 상품 전환, 조건 열람, 재권유, 페이지 이탈, 전송·복귀·내보내기

이벤트에는 순서, 단계, 시각, 해당 구간 경과 시간이 들어갑니다. 단계 이동·페이지 이탈 시 체류 시간을 누계하지만 이는 실제 주시 시간이나 피로 점수가 아닙니다. 최종 확인에서 수정하면 기존 값을 보존한 채 해당 화면으로 이동하며 수정한 비용을 다시 계산합니다.

JSON은 세션과 누적 이벤트를 보존합니다. CSV는 세션·선택·비용·이벤트 행으로 내보내며 UTF-8 BOM을 포함합니다. 파일은 별도 사본이며, 파일 다운로드 성공을 중앙 저장 성공으로 간주하지 않습니다.

## 중앙 수집 서버 연결

`server/`에는 Supabase용 데이터베이스 migration과 Edge Function이 있습니다. 자세한 배포·비밀값·권한·데이터 조회 방법은 [서버 README](server/README.md)를 따릅니다. 현재 계정 연결과 원격 배포가 완료되지 않았으므로 이 소스가 있다는 이유만으로 외부 참가자의 데이터가 서버에 수집되고 있다고 설명하면 안 됩니다.

계정 연결 후 migration과 `moafit-collect` 함수를 배포하고 허용 origin을 확인합니다. 시험 기록을 POST하여 실제 비공개 테이블의 저장을 확인한 뒤, 발급된 HTTPS 함수 주소를 `panel-config.js`의 `collectionUrl`에 넣고 `collectionRequired: true`로 설정합니다. 함수의 GET 상태 확인만으로 저장 검증을 마치지 않습니다.

클라이언트는 세션 ID, 원문 패널 ID, 조사·조건·시험 구분, 양의 `revision`, 선택·비용·누적 이벤트와 세션별 임의 `writeToken`을 JSON으로 전송합니다. 동일 세션의 재시도는 같은 토큰과 갱신 번호를 사용합니다. 서버는 토큰 해시와 불변 필드를 검사하고 트랜잭션으로 갱신합니다. 이미 확인한 과거 요청이나 같은 본문의 재시도는 중복 이벤트·중복 세션을 만들지 않으며, 최종 상태를 과거 진행 상태로 되돌리지 않습니다. CORS는 발신 브라우저의 출처를 제한하며 패널 소속 자체를 인증하는 수단은 아닙니다.

성공 응답의 형식은 다음과 같습니다. 값은 형식 예시이며 실제 저장 건의 응답을 사용합니다.

```json
{
  "ok": true,
  "receiptId": "서버가 발급한 세션별 확인 UUID",
  "sessionId": "요청과 동일한 세션 UUID",
  "ackRevision": 12,
  "lastEventSequence": 12,
  "panelOutcome": "complete"
}
```

클라이언트는 `ok`와 확인 번호뿐 아니라 같은 세션 ID, 보낸 기록 이상인 `ackRevision`·`lastEventSequence`, 요청한 완료·아웃 상태를 확인해야 저장 성공으로 처리합니다. 최종 기록의 확인이 끝나야 설문으로 이동합니다. 오래된 성공 응답, 잘못된 세션이나 낮은 갱신 번호의 응답으로 최종 저장을 완료 처리하지 않습니다. 실패·시간 초과 때에는 기기 내 대기열을 유지하고 재시도를 제공합니다.

수집 서버는 `OPTIONS`·`POST`와 JSON `Content-Type`을 허용하고 `https://saeromlee.kr` 등 실제 배포 origin에만 CORS 응답을 줍니다. 쿠키·관리자 키는 브라우저에서 보내지 않습니다. Supabase 관리자 키는 서버 환경변수에서만 읽으며 앱 파일이나 공개 저장소에 넣지 않습니다. 관리자 조회 권한, 보관 기간, 운영 데이터 관리와 수집 정책은 서버 운영자가 별도 관리합니다.

## 검증과 유지보수

다음 세 명령을 저장소 루트에서 실행합니다. 클라이언트 테스트는 예시 도메인과 가짜 전송 함수를 사용합니다. 서버 테스트는 검증·HTTP 처리를 점검하며, DB 테스트 환경 설치와 실행 조건은 [서버 README](server/README.md#로컬-검증)를 따릅니다.

```text
node --test test/finance-panel-bridge.cjs
node --test test/finance-session-sync.cjs
node --test experiments/dark-pattern-finance/server/*.test.mjs
```

패널 ID 왕복 보존, 완료·아웃 분리, 고정 복귀 URL, 서버 응답 확인, 대기열 재시도, 오래된 응답과 동시 요청 처리, 중복 방지와 최종 상태 보존을 검증합니다. 로컬 테스트 통과는 실제 Supabase 배포·권한 확인이나 엠브레인 운영 접수 검증을 대신하지 않습니다. 현재는 임시 복귀 URL과 시험 코드로 완료·중단을 확인하고, 운영 전에는 패널사가 제공한 시험 ID와 URL로 실제 왕복을 별도로 확인합니다.

두 조건에서 신청·전체 보류, 유료 옵션 전부 해제, 최종 확인 수정, 중간 새로고침, 다른 패널로 입장, 자료 내보내기를 확인합니다. 부정 질문은 표시 문구뿐 아니라 내부 신청·미신청 값도 검증합니다.

대출은 300만원·36개월에 원금과 이자를 매달 같은 금액으로 갚는 근사치입니다. 월 합계에는 대출 원금·이자와 관리·추가 서비스 요금이 포함됩니다. 최초 대출 비용은 별도이며 투자 수수료·환전 및 거래비용·지정 카드 연회비는 월 합계에서 제외합니다. 전체 보류 후의 비용은 검토한 구성의 예상치입니다.

상품·요금을 바꿀 때 계산식과 상품 카드·요약·확인 문구를 함께 갱신합니다. 기존 세션을 재사용하면 안 되는 변경에는 `VERSION`을 갱신하고, 저장 구조를 바꾸면 `schemaVersion`과 복구 조건도 점검합니다. 복귀 주소·코드·조사 ID·시험 구분을 바꿀 때에는 클라이언트 설정과 서버의 `MOA_STUDY_ID`·`MOA_FORCE_TEST`를 함께 점검하고 새 세션으로 검증합니다. 기존 시험 기록과 운영 기록을 섞지 않습니다.
