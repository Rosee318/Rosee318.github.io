# Morrow Finance 모바일 의사결정 체험

이사에 필요한 생활자금 300만원과 여유자금 100만원을 구성하는 연구용 가상 금융 앱입니다. 상품 선택이 뒤 단계의 설정과 예상 비용에 누적되며, 마지막에 구성을 수정하거나 전체 신청을 보류할 수 있습니다. 실제 계좌 개설·대출·투자·환전·결제는 발생하지 않습니다. 상품·요금·이용자 활동 알림은 모의 정보입니다.

설문 문항이나 응답을 생성·수집하는 기능은 없습니다. 이 앱은 선택 과정과 최종 모의 결정을 기록합니다.

## 실행과 URL

별도 빌드나 외부 라이브러리 없이 `index.html`, `app.css`, `app.js`를 같은 디렉터리에서 HTTP(S)로 제공합니다. 배포 경로는 `/experiments/dark-pattern-finance/`입니다.

| 용도                 | URL 예시                                                                                            |
| -------------------- | --------------------------------------------------------------------------------------------------- |
| 다크패턴 조건 참가자 | `https://saeromlee.kr/experiments/dark-pattern-finance/?condition=dark&pid=P001`                    |
| 중립 조건 참가자     | `https://saeromlee.kr/experiments/dark-pattern-finance/?condition=neutral&pid=P002`                 |
| 다크패턴 조건 연구자 | `https://saeromlee.kr/experiments/dark-pattern-finance/?condition=dark&researcher=1&pid=TEST001`    |
| 중립 조건 연구자     | `https://saeromlee.kr/experiments/dark-pattern-finance/?condition=neutral&researcher=1&pid=TEST002` |

`condition=neutral` 이외에는 다크패턴 조건이 적용됩니다. `researcher=1`이면 단계별 자극 설명, 조건 전환, 현재 기록 확인과 내보내기를 사용할 수 있습니다. 참가자에게는 이 매개변수를 제거한 주소를 전달합니다. 연구자 패널의 조건 전환 링크에는 `pid`가 이어지지 않으므로, 특정 익명 코드로 확인할 때는 주소에 다시 지정합니다.

`pid`는 선택 사항인 익명 참가자 코드입니다. 영문·숫자·밑줄·하이픈만 남기며 최대 48자입니다. 이름·연락처·실제 금융정보를 넣지 않습니다.

## 8단계 흐름과 자극

시작 화면에서 과제를 확인한 뒤 다음 8단계를 진행합니다. 최종 결정 후 완료 화면에서 기록을 저장할 수 있습니다.

| 단계           | 선택 내용                                    | 다크패턴 조건의 표현                                                                                                                                                         |
| -------------- | -------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. 연결 계좌   | Flex Save 또는 Basic                         | T04 숨겨진 정보: 최대 연 5.2%의 세부 적용 조건을 접힌 항목 안에 배치                                                                                                         |
| 2. 대출 비교   | Loan A, Loan B 또는 대출 신청 안 함          | T05 가격비교 방해: 상품을 전환해야 다른 상품의 조건을 확인                                                                                                                   |
| 3. 투자 구성   | Growth 60, Balance 40 또는 계좌에 보관       | T07 다른 소비자의 활동 알림: 조회·최근 선택 인원 제시                                                                                                                        |
| 4. 관리 플랜   | 무료 Basic 또는 월 9,900원 Smart Plus        | T02a 잘못된 계층구조: 설명 카드와 선택 버튼의 순서 대응을 어긋나게 구성. T02b 감각조작: 움직이는 강조 배너와 9초 뒤 재권유. 미선택 상태에서 추천 구성으로 계속하면 Plus 선택 |
| 5. 추가 서비스 | 해외시황 알림·잔액보호 리포트 유지 또는 해제 | T03 특정옵션의 사전선택: 첫 방문 시 두 유료 항목을 체크                                                                                                                      |
| 6. 자동환전    | 신청 또는 신청 안 함                         | T01 속임수 질문: 질문과 응답에 부정 표현을 반복                                                                                                                              |
| 7. 혜택 설정   | Morrow Care 신청 또는 신청 안 함             | T06 감정적 언어사용: 거절자를 부정적으로 묘사하는 문구                                                                                                                       |
| 8. 최종 확인   | 항목별 수정, 모의 신청 또는 전체 신청 보류   | 현재 선택과 예상 비용을 함께 확인하고 확인 대화상자에서 최종 결정                                                                                                            |

중립 조건은 상품·요금·과제를 유지하면서 금리 조건을 바로 보여 주고, 대출 비교표와 두 상품을 함께 제시합니다. 활동 알림·움직이는 권유 배너를 제거하고, 플랜을 명시적으로 선택하게 하며, 추가 서비스는 처음부터 해제합니다. 자동환전과 Morrow Care에는 직접적인 신청·거절 문구를 사용합니다.

## 저장과 기록 해석

선택과 진행 상태는 해당 브라우저 탭의 `sessionStorage`에 보관됩니다. 같은 조건·익명 코드·앱 버전이면 새로고침 후 이어집니다. 탭을 닫거나 새 체험을 시작하기 전에 완료 화면의 JSON 또는 CSV 저장 기능으로 필요한 기록을 내려받습니다. 서버 자동 수집·전송은 없으며, 연구자에게 제출하려면 파일을 별도로 전달해야 합니다.

- `sessionId`, `participantCode`, `condition`, `appVersion`: 세션과 조건 식별 정보
- `initialChoices`: 항목에 처음 기록된 값. 추가 서비스의 사전 체크도 포함하므로 최초의 명시적 사용자 선택과 동일하게 해석하지 않음
- `choices`: 마지막으로 구성한 선택. 전체 신청을 보류한 경우에도 검토한 구성으로 보존
- `finalDecision`: 모의 신청은 `apply`, 전체 신청 보류는 `decline`. 실제 적용 여부는 이 값과 함께 해석
- `final_decision` 이벤트: 최종 확정 시 선택·비용의 사본. `costSnapshot`과 화면 비용은 검토한 구성의 예상치
- `events`: `choice`, `choice_change`, 기본값 설정, 단계 진입·이탈, 자극 노출, 상품 전환, 조건 열람, 재권유, 페이지 이탈과 내보내기 기록

각 이벤트에는 순서, 단계, 시각, 해당 구간 경과 시간이 포함됩니다. 단계 이동과 페이지 이탈 시 체류 시간을 누계합니다. 이는 브라우저 경과 시간이며 실제 주시 시간이나 피로 정도를 뜻하지 않습니다. 최종 확인의 수정은 기존 값을 보존한 채 해당 화면으로 이동하고, 변경한 값을 다시 최종 확인에 반영합니다.

JSON은 세션 전체와 이벤트를 보존합니다. CSV는 `session`, `session_meta`, `initial_choice`, `final_choice`, `cost`, `event` 행으로 내보내며 한글 확인을 위해 UTF-8 BOM을 포함합니다.

## 비용과 유지보수

대출은 300만원·36개월 원리금균등상환의 근사치로 계산합니다. 월 합계에는 대출 원리금과 관리 플랜·추가 서비스 요금이 포함됩니다. 최초 취급수수료는 별도이며, 투자 보수·환전 및 거래비용·제휴카드 연회비는 월 합계에서 제외된다고 화면에 안내합니다. 전체 보류 결과의 비용은 검토한 구성의 예상 비용입니다.

- `index.html`: 앱의 기본 영역, 메타데이터와 파일 연결
- `app.css`: 모바일 레이아웃, 조건별 배치·강조·움직임
- `app.js`: 단계별 문구, 상태 전환, 상품 조건, 비용, 기록·복구·내보내기

상품이나 요금을 바꿀 때는 계산식과 상품 카드·요약·확인 문구를 함께 갱신합니다. 단계나 선택 항목을 바꾸면 `steps`, `mechanismMap`, 화면 함수, 진행 검증, 요약·내보내기도 함께 점검합니다. 기존 세션을 재사용하면 안 되는 변경에는 `VERSION`을 갱신하고, 저장 구조를 바꾸면 `schemaVersion`과 복구 조건도 검토합니다.

수정 후에는 두 조건에서 신청·전체 보류, 모든 유료 옵션 해제, 최종 확인에서 수정, 중간 새로고침, 익명 코드 변경, JSON·CSV 내보내기를 확인합니다.
