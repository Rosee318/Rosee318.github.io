# 모아핏 모바일 의사결정 체험

이사에 필요한 생활자금 300만원과 여윳돈 100만원을 관리할 구성을 고르는 연구용 가상 금융 앱입니다. 상품 선택이 다음 단계의 설정과 예상 비용에 누적되며, 마지막에 구성을 수정하거나 전체 신청을 보류할 수 있습니다. 실제 계좌 개설·대출·투자·환전·결제는 발생하지 않습니다. 상품·요금·이용자 활동 알림은 연구용 모의 정보입니다.

설문 문항이나 응답을 생성·수집하지 않습니다. 앱의 선택·행동 기록과 최종 모의 결정을 남기며, 운영 설정이 갖춰지면 체험 후 엠브레인 설문으로 패널 ID와 상태값을 전달합니다.

## 실행 파일과 현재 연동 상태

별도 빌드나 외부 라이브러리 없이 다음 파일을 같은 디렉터리에서 HTTP(S)로 제공합니다. 배포 경로는 `/experiments/dark-pattern-finance/`입니다.

- `index.html`: 화면의 기본 영역과 스크립트 연결
- `app.css`: 모바일 레이아웃, 읽기 쉬운 글자·버튼, 조건별 배치와 강조
- `panel-config.js`: 조사 ID, 운영 복귀 주소·상태 코드, 선택적인 기록 수집 주소
- `panel-bridge.js`: 패널 ID 검증·보존, 복귀 URL 생성, 선택적인 서버 저장
- `app.js`: 단계별 문구, 상품 조건, 선택과 비용, 진행·기록·복구·복귀 화면

현재 `panel-config.js`는 `enabled: false`이며 완료·아웃 복귀 주소와 상태 코드가 빈 값입니다. **패널 ID를 받는 기능과 복귀 처리 코드는 준비되어 있지만 실제 엠브레인 연동은 아직 완료되지 않았습니다.** 운영용 주소·코드를 확정하고 실제 패널사와 왕복 검증한 뒤 활성화합니다. 예시의 `XXXX` 주소나 예시 상태값을 운영값으로 채우지 않습니다.

## 참가자와 연구자 URL

| 용도                        | URL 예시                                                                                              |
| --------------------------- | ----------------------------------------------------------------------------------------------------- |
| 다크패턴 조건의 패널 참가자 | `https://saeromlee.kr/experiments/dark-pattern-finance/?condition=dark&panel_id=P001`                 |
| 중립 조건의 패널 참가자     | `https://saeromlee.kr/experiments/dark-pattern-finance/?condition=neutral&panel_id=P002`              |
| 연구자 확인                 | `https://saeromlee.kr/experiments/dark-pattern-finance/?condition=dark&researcher=1&panel_id=TEST001` |
| 패널 복귀 없는 일반 체험    | `https://saeromlee.kr/experiments/dark-pattern-finance/?condition=dark`                               |
| 기존 익명 코드 방식         | `https://saeromlee.kr/experiments/dark-pattern-finance/?condition=neutral&pid=P003`                   |

위 ID는 URL 형식을 보여 주는 예시입니다. 실제 링크는 엠브레인이 전달하는 ID를 사용합니다. `condition=neutral` 이외에는 다크패턴 조건이 적용됩니다. `researcher=1`은 자극 설명과 현재 기록·내보내기를 확인하는 연구자용 표시이므로 참가자 링크에서 제거합니다. 연구자 패널에서 조건을 전환하면 패널 ID가 이어지지 않을 수 있으므로, 참가자 입장 링크는 위 형식으로 별도 구성합니다.

`panel_id`가 있거나 `panel=1`이면 패널 모드입니다. `panel_id`는 `pid`보다 우선하며, 읽은 ID의 문자나 대소문자를 임의로 제거·변환·잘라내지 않습니다. 앞뒤 공백도 포함해 유효한 원문을 그대로 기록과 복귀에 사용합니다. 다음 입력은 원문을 바꾸는 대신 오류로 처리합니다.

- ID가 없거나 빈 값·공백만 있는 값
- `panel_id`가 여러 번 들어 있는 링크
- 512자를 넘거나 제어 문자를 포함한 값
- `[ID]` 등 예시 문자가 그대로 남은 값

패널사는 ID를 URL 쿼리 값으로 인코딩해야 합니다. 특히 ID 안의 `+`는 `%2B`, `&`는 `%26`으로 전달해야 합니다. 앱은 `URLSearchParams`로 한 번 읽고 복귀 주소에도 같은 방식으로 설정하여 이중 인코딩을 피합니다.

기존 `pid`는 패널 모드가 아닐 때 지원하는 선택적 익명 코드입니다. 기존 방식대로 영문·숫자·밑줄·하이픈만 남기고 최대 48자로 제한합니다. 이 필터는 `panel_id`에는 적용하지 않습니다. 이름·연락처·실제 금융정보를 ID에 넣지 않습니다.

## 한국어 명칭과 8단계 흐름

시작 화면에서 과제를 확인한 뒤 다음 8단계를 진행합니다. 금리·요금·기간은 유지하고 상품명과 설명을 쉬운 한국어로 바꿨습니다. 내부 선택값은 기록 호환성을 위해 유지합니다.

| 구분        | 화면 표시명                     | 내부 값                         |
| ----------- | ------------------------------- | ------------------------------- |
| 저축        | 차곡차곡 적금                   | `account: flex`                 |
| 입출금 통장 | 자유 입출금 통장                | `account: basic`                |
| 대출        | 든든 생활대출 / 알뜰 생활대출   | `loan: A` / `B`                 |
| 투자        | 주식 중심 투자 / 채권 중심 투자 | `portfolio: growth` / `balance` |
| 관리 방식   | 기본 관리 / 맞춤 관리           | `plan: basic` / `plus`          |
| 추가 혜택   | 지출관리 플러스                 | `care: yes` / `no`              |

| 단계           | 선택 내용                                       | 다크패턴 조건의 표현                                                                                                                                                              |
| -------------- | ----------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. 이용할 통장 | 차곡차곡 적금 또는 자유 입출금 통장             | T04 숨겨진 정보: 최대 연 5.2%의 적용 조건을 접힌 항목 안에 배치                                                                                                                   |
| 2. 대출 비교   | 든든 생활대출, 알뜰 생활대출 또는 신청 안 함    | T05 가격비교 방해: 상품을 전환해야 다른 상품 조건을 확인                                                                                                                          |
| 3. 투자 구성   | 주식 중심 투자, 채권 중심 투자 또는 계좌에 보관 | T07 다른 소비자의 활동 알림: 조회·최근 선택 인원 제시                                                                                                                             |
| 4. 관리 방식   | 무료 기본 관리 또는 월 9,900원 맞춤 관리        | T02a 잘못된 계층구조: 설명 카드와 선택 버튼의 대응 순서를 어긋나게 구성. T02b 감각조작: 움직이는 강조 배너와 9초 뒤 재권유. 미선택 상태에서 추천 구성으로 계속하면 맞춤 관리 선택 |
| 5. 추가 서비스 | 해외시황 알림·잔액보호 보고서 유지 또는 해제    | T03 특정옵션의 사전선택: 첫 방문 때 두 유료 항목을 체크                                                                                                                           |
| 6. 자동환전    | 신청 또는 신청 안 함                            | T01 속임수 질문: 신청을 원하지 않는지 묻는 부정 질문과 예·아니요 선택                                                                                                             |
| 7. 혜택 설정   | 지출관리 플러스 신청 또는 신청 안 함            | T06 감정적 언어사용: 거절자를 부정적으로 묘사하는 문구                                                                                                                            |
| 8. 최종 확인   | 항목 수정, 모의 신청 또는 전체 신청 보류        | 현재 선택과 예상 비용을 확인한 뒤 대화상자에서 최종 결정                                                                                                                          |

자동환전의 실험 조건 질문은 “신청을 원하지 않으시나요?”입니다. **예는 미신청(`autoFx: no`), 아니요는 신청(`autoFx: yes`)**으로 저장합니다. 중립 조건의 긍정형 질문에서는 예가 신청, 아니요가 미신청입니다.

중립 조건은 상품·요금·과제를 유지하면서 금리 조건을 바로 보여 주고, 대출 비교표와 두 상품을 함께 제시합니다. 활동 알림·움직이는 권유 배너는 없고 관리 방식을 명시적으로 선택합니다. 추가 서비스는 처음부터 해제되며, 자동환전과 지출관리 플러스에는 중립적인 신청·거절 문구를 사용합니다.

## 엠브레인 왕복 설정

운영 흐름은 **엠브레인 설문 → `panel_id`와 함께 체험 앱 입장 → 체험 종료 → ID·상태값과 함께 엠브레인 설문 복귀**입니다. 패널사가 뒤쪽 설문을 이어서 보여 주고 최종 조사를 종료합니다.

`panel-config.js`에 패널사가 확정한 값만 입력합니다.

| 설정                 | 의미와 현재 값                                          |
| -------------------- | ------------------------------------------------------- |
| `enabled`            | 실제 복귀 활성화. 현재 `false`                          |
| `studyId`            | 조사 구분값. 현재 `finance-decision-20261120`           |
| `completeReturnUrl`  | 체험 완료 시 돌아갈 고정 운영 URL. 현재 빈 값           |
| `outReturnUrl`       | 아웃 시 돌아갈 고정 운영 URL. 현재 빈 값                |
| `completeStatus`     | 패널사가 지정한 완료 코드 문자열. 현재 빈 값            |
| `outStatus`          | 패널사가 지정한 아웃 코드 문자열. 현재 빈 값            |
| `exitIsOut`          | 명시적인 체험 중단을 아웃으로 보낼지 여부. 현재 `false` |
| `redirectDelayMs`    | 준비 완료 후 복귀 이동까지 대기 시간. 현재 1,200ms      |
| `collectionUrl`      | 선택적인 앱 기록 수집 서버 URL. 현재 빈 값              |
| `collectionRequired` | 수집 주소가 없을 때 복귀를 차단할지 여부. 현재 `false`  |

완료·아웃 주소가 같더라도 각 항목에 지정합니다. 상태 코드는 선행 0이 보존되도록 숫자가 아닌 문자열로 설정합니다. 사용자 예시의 `status=001`은 운영 완료 코드로 확정된 값이 아닙니다.

참가자 URL에 임의로 넣은 `return_url`은 사용하지 않습니다. 복귀 주소는 배포된 운영 설정 파일에서만 읽으며, 원래 주소의 조사별 쿼리는 보존한 채 `panel_id`와 `status`만 설정합니다. 이미 같은 이름의 쿼리가 있으면 새 값 하나로 대체하고 URL 조각(`#...`)은 제거합니다. `XXXX`, `[ID]` 등 예시 값이 남은 복귀 주소는 차단합니다.

### 체험 결과와 패널 상태의 구별

- 최종 모의 신청(`finalDecision: apply`)과 전체 신청 보류(`finalDecision: decline`)는 **둘 다 체험 완료(`panelOutcome: complete`)**입니다. 금융상품을 거절했다고 아웃으로 처리하지 않습니다.
- 아웃 기준은 패널사·연구자가 별도로 확정해야 합니다. 임의의 나이·선택 결과·시간 기준으로 참가자를 제외하지 않습니다.
- 명시적 중단을 아웃으로 보내기로 승인한 경우에만 `exitIsOut: true`를 설정합니다. 그러면 중단 확인을 거쳐 `panelOutcome: out`, 사유 `participant_exit`를 기록하고 아웃 코드로 복귀합니다.
- 창을 닫는 것만으로 복귀 이동을 보장할 수 없습니다. 창 닫기를 자동으로 아웃이라고 전송하지 않습니다.

운영 주소나 코드가 없으면 실제 패널사로 이동하지 않고 설정 대기 화면을 표시합니다. 정상 설정에서 체험이 끝나면 복귀 준비와 선택적 서버 저장 후 이동합니다. 저장·연결 실패 시 기록을 해당 탭에 유지하고 다시 연결할 수 있습니다. 이미 이동을 시도한 화면을 다시 열었을 때는 자동으로 반복 이동하지 않고 재이동 버튼을 표시합니다. `panelReturn.state: returned`는 브라우저의 이동 시도 기록이며 엠브레인 서버의 수신 성공 확인을 뜻하지 않습니다.

## 기록 저장과 세션 복구

기본 기록은 해당 브라우저 탭의 `sessionStorage`에 보관됩니다. 새로고침 복구 시 저장 형식(`schemaVersion`), 앱 버전, 실험 조건, 참가자 코드, 정확한 `panel_id`, `studyId`, 진행 단계가 일치해야 합니다. 다른 패널·다른 조사·다른 조건의 기록을 이어서 사용하지 않습니다. 기존 `pid` 체험과 패널 모드도 구분합니다.

`collectionUrl`을 지정하지 않으면 **앱 전체 기록이 중앙 서버에 자동 누적되지 않습니다.** 브라우저 기록·파일 내보내기와 설정된 엠브레인 주소로의 ID·상태값 복귀만 수행합니다. 엠브레인 복귀 URL에 전체 선택·행동 기록을 붙여 보내지는 않습니다. 일반 체험에서는 완료 화면에서 자료를 저장할 수 있고, 패널 체험의 기록은 연구자 모드에서 확인·내보낼 수 있습니다.

- `sessionId`, `participantCode`, `panel_id`, `studyId`, `condition`, `appVersion`: 참가자·조사·조건 식별
- `initialChoices`: 항목에 처음 기록된 값. 사전 체크도 포함하므로 최초의 명시적 사용자 선택과 동일하게 해석하지 않음
- `choices`: 마지막으로 구성한 선택. 전체 신청 보류 시에도 검토한 구성을 보존
- `finalDecision`: 모의 신청 `apply`, 전체 보류 `decline`
- `panelOutcome`, `panelStatus`, `panelReturn`: 패널 처리 결과, 실제 운영 코드, 저장·복귀 진행 상태
- `final_decision` 이벤트와 `costSnapshot`: 최종 확정 시 선택·비용 사본
- `events`: 선택·수정, 기본값, 단계 진입·이탈, 자극 노출, 상품 전환, 조건 열람, 재권유, 페이지 이탈, 기록 전송·복귀·내보내기

이벤트에는 순서, 단계, 시각, 해당 구간 경과 시간이 들어갑니다. 단계 이동·페이지 이탈 시 체류 시간을 누계하지만 이는 실제 주시 시간이나 피로 점수가 아닙니다. 최종 확인에서 수정하면 기존 값을 보존한 채 해당 화면으로 이동하며, 수정한 비용을 다시 계산합니다.

JSON은 세션과 전체 이벤트를 보존합니다. CSV는 `session`, `session_meta`, `initial_choice`, `final_choice`, `cost`, `event` 행을 사용하고 한글 확인을 위한 UTF-8 BOM을 포함합니다. 탭을 닫거나 새 체험을 시작하기 전에 필요한 파일을 저장합니다.

## 선택적인 중앙 수집 서버 계약

중앙 수집이 필요하면 운영자가 관리하는 HTTPS 서버를 `collectionUrl`로 지정합니다. 로컬 시험에서는 루프백 HTTP 주소도 허용합니다. 앱에 서버 비밀키나 관리자 자격증명을 넣지 않습니다.

앱은 `Content-Type: application/json`인 `POST`로 세션 기록에 다음 값을 포함해 전송합니다.

- 원문 `panel_id`, `studyId`, `sessionId`
- `panelOutcome`, 확정된 `panelStatus`
- 선택·비용·이벤트를 포함하는 기록
- `idempotencyKey`: `studyId:sessionId:outcome` 형식의 중복 방지 키

서버는 중복 방지 키를 영속적으로 저장하여 같은 완료 요청을 새로고침·재시도로 다시 받아도 한 건으로 처리해야 합니다. 브라우저 안의 동시 요청·성공 응답 재사용만으로 새로고침 이후 중복 저장까지 보장할 수는 없습니다.

저장이 확인되면 서버는 성공 HTTP 응답과 아래 형식의 JSON을 반환합니다. `receiptId`는 실제 저장 건을 식별하는 비어 있지 않은 문자열이어야 합니다.

```json
{ "ok": true, "receiptId": "record-0001" }
```

위 응답은 형식 예시입니다. 앱은 `ok: true`와 `receiptId`를 모두 확인한 후 설문으로 복귀합니다. 수집 주소가 지정된 경우 저장 실패·잘못된 응답·시간 초과가 발생하면 복귀를 보류하고 재시도를 제공합니다. `collectionRequired: true`이면 수집 주소가 비어 있을 때도 복귀를 차단합니다.

수집 서버가 다른 출처에 있으면 브라우저의 CORS 사전 요청을 처리해야 합니다. 허용 출처는 실제 배포 주소인 `https://saeromlee.kr`로 지정하고, `OPTIONS`와 `POST`, `Content-Type` 헤더를 허용합니다. 앱은 쿠키·자격증명을 보내지 않는 요청(`credentials: omit`)을 사용합니다. 접근 통제·보관 기간·서버 검증·속도 제한은 수집 서버에서 별도 운영합니다.

## 검증과 유지보수

저장 기록과 ID가 실제 패널사로 전송될 수 있으므로 운영 주소에 가짜 테스트 완료를 보내지 않습니다. 아래 테스트는 예시 도메인과 가짜 전송 함수를 사용합니다.

```text
node --test test/finance-panel-bridge.cjs
```

패널 ID의 특수문자·한글 왕복 보존, 중복·빈 ID 거절, 고정 복귀 주소와 기존 쿼리 보존, 설정 누락·예시 주소 차단, 신청 보류의 완료 처리, 다른 패널·조사의 기록 거절, 서버 응답 확인·실패 후 재시도·중복 방지를 검증합니다. 실제 운영 전에는 패널사가 제공한 시험용 ID와 URL로 설문 → 체험 → 설문의 왕복을 별도로 확인합니다.

두 조건에서 신청·전체 보류, 유료 옵션 전부 해제, 최종 확인 수정, 중간 새로고침, 다른 패널로 입장, 자료 내보내기를 확인합니다. 부정 질문은 표시 문구뿐 아니라 내부 신청·미신청 값도 검증합니다.

대출은 300만원·36개월에 원금과 이자를 매달 같은 금액으로 갚는 근사치입니다. 월 합계에는 대출 원금·이자와 관리·추가 서비스 요금이 포함됩니다. 최초 대출 비용은 별도이며 투자 수수료·환전 및 거래비용·지정 카드 연회비는 월 합계에서 제외합니다. 전체 보류 후의 비용은 검토한 구성의 예상치입니다.

상품·요금을 바꿀 때 계산식과 상품 카드·요약·확인 문구를 함께 갱신합니다. 기존 세션을 재사용하면 안 되는 변경에는 `VERSION`을 갱신하고, 저장 구조를 바꾸면 `schemaVersion`과 복구 조건도 점검합니다. 복귀 주소·코드·아웃 기준을 바꿀 때에는 패널사와 합의한 설정값을 재확인합니다.
